# Масові команди M2M

Streamlit-застосунок для платформи M2M (`my.m2m.eu`): створює команду «Надіслати довільне повідомлення
(custom_msg)» на всіх об'єктах вибраної групи, масово надсилає її і збирає відповіді трекерів
(«Результат команди»). Розрахований на великі групи (500+ об'єктів, наприклад, «Генератори»): усі запити йдуть
пачками з паузами, щоб не перевантажити сервер.

## Як користуватись

1. **Вхід**: сервер, email і пароль від my.m2m.eu. Пароль живе лише в пам'яті сесії й ніде не зберігається.
2. **Навантаження фіксоване** (налаштувань немає): пачки по 50 об'єктів, до 4 запитів одночасно, 2 с паузи між
   пачками, до 2 повторів при збоях читання; відповіді опитуються кожні 15 с, «останнє повідомлення» під час
   очікування — раз на хвилину. Для групи на 100 об'єктів це 2 пачки, на 534 — 11.
3. **Вкладка «1 · Створення команди»**
   - група, ім'я команди (до 50 символів) і текст (до 255). Одразу підставлені «NTP» і
     `runcmd:@com_tsync_disallow:1`; інші значення за замовчуванням задаються в Secrets
     (`DEFAULT_COMMAND_NAME`, `DEFAULT_COMMAND_TEXT`);
   - «Перевірити групу» читає команди кожного об'єкта й показує: скільки буде створено, у скількох команда з таким
     ім'ям уже є, у скількох немає права «Створення команд». Таблиця всіх об'єктів — у розгортці;
   - «Створити на N об'єктах»: прогрес, лічильники, таблиця статусів з фільтром, «Зупинити», «Повторити помилки»,
     звіт CSV.
   - Якщо на об'єкті вже є команда з таким ім'ям — **пропускаємо**, дубль не створюємо.
4. **Вкладка «2 · Відправка і результати»**
   - група → команда (список зібрано з команд об'єктів групи) → текст. Якщо під тим самим ім'ям на частині
     об'єктів інший текст, ці об'єкти пропускаються, і про це видно попередження;
   - **Активність об'єктів**: смуга «Онлайн (≤ N хв) / За добу / Давніше або ніколи» за часом останнього
     повідомлення. Перемикач «Онлайн — першими» (увімкнений) надсилає спершу свіжим об'єктам, далі за давністю,
     тож відповіді з'являються одразу, а «сплячі» йдуть у кінці черги;
   - кому надсилати: усім / лише онлайн / тим, хто не відповів минулого разу;
   - **звірка** (увімкнена за замовчуванням): «Не надсилати тим, хто вже прийняв команду» — за статистикою з
     GitHub і запусками сесії об'єкти, від яких уже є «Результат команди», пропускаються. Повторна відправка
     через годину чи завтра йде лише тим, хто ще не прийняв;
   - скільки чекати відповідь (15 хв);
   - під час очікування «останнє повідомлення» тих, хто ще не відповів, перечитується кожну хвилину (один запит
     на всю групу): видно, хто вийшов на зв'язок після відправки, а хто мовчить. Якщо
     ніхто з тих, хто чекає, на зв'язок не виходив, застосунок підкаже, що чекати далі немає сенсу;
   - «Надіслати на N об'єктів»: прогрес відправки, потім таймер очікування; «Відповіли за активністю» по кожній
     групі; таблиця з колонками №, Об'єкт, Активність, Останнє повідомлення, Надіслано, Статус, Відповідь трекера,
     Отримано, IMEI; фільтр; «Перевірити відповіді ще раз» (дочитати пізні), «Ще раз — без відповіді», звіт CSV.
   - **«Статистика по групі (CSV)»** — кожен об'єкт групи: застосовано (трекер відповів) чи ні і чому
     («Надіслано, відповіді немає — повторити», «Помилка відправки — повторити», немає команди, інший текст, немає права, не надсилали), коли відповів,
     скільки разів надсилали. Зведено з усіх запусків цієї команди на групу в поточній сесії (перший запуск +
     «Ще раз — без відповіді»). Після перезавантаження сторінки історія запусків не зберігається — завантажте CSV.

## Статистика (вкладка «3 · Статистика»)

Усі групи: скільки об'єктів, скільки прийняли команду (трекер відповів), чи перевірялась група і коли. Група
розкривається: спершу об'єкти, що прийняли (з відповіддю й часом), потім ті, що ні (з причиною). Повторні
запуски на тій самій групі доповнюють статистику: хто хоч раз прийняв — лишається «прийняв».

Показуються лише групи, **створені користувачем `STATS_OWNER_EMAIL`** (за замовчуванням alona.suprun@kyivstar.net;
визначається за творцем групи через `/api/device/groups`). Порядок: спершу перевірені (свіжіші вище), потім групи
з `_OVA` / `_KS` у назві (`STATS_PRIORITY_TAGS`), потім решта за алфавітом. Для іншого клієнта — змініть Secrets.

Після кожного запуску статистика автоматично дописується в цей репозиторій, у **гілку `stats`**
(папка `stats/<команда>/`: `data.json`, `groups.csv`, `objects.csv` — GitHub показує CSV як таблиці).
Гілка окрема, бо пуш у `main` перезапустив би застосунок на Streamlit посеред розсилки. `main` не змінюється.

Потрібен токен у Secrets застосунку:

```toml
GITHUB_TOKEN = "github_pat_..."   # fine-grained token: Repository access → лише mass_comand_sent,
                                  # Permissions → Contents: Read and write
# GITHUB_REPO = "Oleksandr-Rosenko/mass_comand_sent"   # за замовчуванням
# GITHUB_BRANCH = "stats"                              # за замовчуванням
```

Без токена статистика працює лише в межах сесії.

## Що застосунок робить на платформі (і нічого більше)

Лише три дії, які змінюють дані, і тільки після натискання кнопки: **створює команду** на об'єкті (якщо команди
з таким ім'ям там ще немає) і **надсилає команду** на об'єкт; плюс вхід. Усе інше — читання. Застосунок ніколи не
редагує й не видаляє команди, об'єкти, групи чи налаштування (у коді немає жодного PUT/DELETE/PATCH; це перевіряє
тест `test_full_cycle_makes_only_allowed_requests`) і не позначає сповіщення прочитаними.

Побічний ефект самої платформи: «Результат команди» з'являється в сповіщеннях у всіх, хто має доступ до об'єкта
(як і при ручній відправці).

## Як це працює (API)

| Крок | Запит |
|---|---|
| Вхід | `POST /api/login`, оновлення токена — `POST /api/token/refresh` (або повторний вхід) |
| Групи | `GET /api/device/groups/lightweight/all` (усі групи з id об'єктів) |
| Об'єкти групи | `GET /api/group/{groupId}/devices` (назва, IMEI, останнє повідомлення, права) |
| Команди об'єкта | `GET /api/device/{id}/commands` |
| Створення | `POST /api/device/{id}/commands` з `{"description": ім'я, "type": "CUSTOM", "attributes": {"data": текст}}` — так само, як форма «Нова команда» |
| Відправка | `POST /api/device/{id}/command/{commandId}/dispatch` — групового методу немає, застосунок проходить об'єкти пачками |
| Відповіді | `GET /api/notification/history?type=COMMAND_RESULT` |

**Зіставлення відповідей.** Перед відправкою запам'ятовується найбільший id в історії «Результат команди».
Відповіддю об'єкта вважається перший новіший запис із його `deviceId`, створений не раніше ніж за 2 хв до
відправки на цей об'єкт. Історію бачать усі, хто має доступ до об'єкта, тож якщо хтось інший одночасно надсилає
команди на ті самі об'єкти, їхні відповіді теж можуть потрапити в звіт.

**Захист від дублів.** Створення й відправка не повторюються навмання: повтор лише тоді, коли сервер точно не
виконав запит (немає з'єднання, 429, 503). Якщо створення завершилось збоєм 5xx або обривом, застосунок перечитує
команди об'єкта й перевіряє, чи команда все ж створилась. Відправку, яку сервер не підтвердив, не повторюємо
(щоб не надіслати двічі), але відповідь на неї чекаємо.

**Офлайн-об'єкти.** Що робить платформа з командою для офлайн-об'єкта (черга чи помилка), невідомо, тому
застосунок просто фіксує відповідь сервера й чекає «Результат команди» заданий час.

## Запуск локально

```bash
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # за потреби
streamlit run app.py
```

Перевірка без бойового сервера — фейковий API з групою «Генератори» на 534 об'єкти (частина без прав, частина
вже з командою, збої 503/500, «сплячі» об'єкти без відповіді):

```bash
python -m tests.fake_api        # http://127.0.0.1:8765, пароль demo123
python -m pytest -q             # тести клієнта й завдань
```

## Streamlit Community Cloud

1. New app → цей репозиторій, гілка `main`, **Main file path: `app.py`**.
2. App → Settings → **Secrets** (необов'язково): вміст `.streamlit/secrets.toml.example` —
   адреса сервера й команда за замовчуванням.

## Структура

- `app.py` — інтерфейс (вхід, бічна панель, дві вкладки);
- `m2m_commands/client.py` — клієнт API (токен, повтори, групи, команди, історія результатів);
- `m2m_commands/jobs.py` — фонові завдання: перевірка групи, створення, відправка з очікуванням відповідей;
- `m2m_commands/stats.py`, `m2m_commands/github_store.py` — статистика по групах і її збереження в гілку `stats`;
- `tests/` — фейковий API і тести.
